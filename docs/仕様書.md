# 持株会 会員管理マクロ 仕様書（Excel VBA）

## ■1 要約

親会社株の持株会をグループ全体で管理するための Excel VBA 業務システム。
利用者が編集するのは「イベント入力」シートのみとし、会員マスタ・拠出設定・
イベント履歴・月次実績はすべてマクロが更新する。履歴は物理削除せず、
処理は何度でも安全に再実行できるように設計している。

## ■2 前提条件

- Excel マクロ有効ブック（.xlsm）として運用する。
- VBA 標準ライブラリの `Scripting.Dictionary`（Microsoft Scripting Runtime
  または `CreateObject("Scripting.Dictionary")`）が使用できること。
- 各シートの1行目は見出し行、2行目以降がデータ行という構成を全シート共通とする。
- 列の物理的な位置（列番号）はコード内にハードコーディングせず、
  1行目の見出し文字列から動的に構築した「ヘッダー列マップ」経由でのみ参照する。
  そのため列の追加・入替が発生してもマクロ本体の改修は不要。
- 主キーは `MemberNo`（会員番号）とし、社員番号は使用しない。

## ■3 シート仕様

シート構成は元仕様の9シートに加え、Step9（スナップショット出力）の
出力先として「スナップショット」シートを1枚追加している
（元仕様のシート構成一覧には無いが、スナップショットを出力するシートが
必須のため拡張余地として追加。ヘッダー列マップ方式のため他シートへの
影響はない）。

## ■4 入出力仕様

- **入力**: イベント入力シートの「処理状態」が空欄または「未処理」の行のみが処理対象。
  「処理済」の行は再実行時に読み飛ばす。
- **出力**:
  - イベント入力: 処理状態／処理日時／エラー内容を更新
  - 会員マスタ／拠出設定／イベント履歴: 業務処理内容に応じて追加・更新
  - 月次実績: 「月次実績更新」実行時に対象年月分をUpsert
  - スナップショット: 「スナップショット出力」実行時にデータ行をクリアしてから再出力
  - 操作ログ: 各処理の実行結果を追記

## ■5 処理フロー

### 5.1 イベント入力反映（`Pr_イベント入力反映実行`）
1. 環境抑止
2. 入力取得（イベント入力シート・ヘッダー列マップ・最終行）
3. 入力チェック（行ごとに必須項目・整合性を検証、エラーはCollectionへ集約）
4. マスタ取得（会員マスタ辞書を事前ロード）
5. 業務処理（イベント種別ごとに Select Case で分岐し、以下の順で更新)
   - イベント履歴へ追加（イベントNo採番）
   - 会員マスタ更新（現在状態）
   - 拠出設定更新（履歴管理: 終了→新規）
6. 出力（イベント入力シートの処理状態等を更新）
7. ログ（操作ログへ成功/エラー件数を記録）
8. 環境復元

### 5.2 月次実績更新（`Pr_月次実績更新実行`）
1. 環境抑止
2. 入力取得（対象年月。省略時は設定シート「処理対象年月」）
3. 入力チェック（年月フォーマット検証）
4. マスタ取得（対象年月時点で有効な拠出設定一覧、会員マスタ）
5. 業務処理（会員ごとに会社コード・単価を取得し評価額を算出）
6. 出力（月次実績シートへUpsert）
7. ログ
8. 環境復元

### 5.3 スナップショット出力（`Pr_スナップショット出力実行`）
1. 環境抑止
2. 入力取得（対象年月）
3. 入力チェック（年月フォーマット検証）
4. マスタ取得（会員マスタ全件、会社名辞書）
5. 業務処理（在籍判定: 入会日<=月末 かつ (退会日が空 または 退会日>月末)）
6. 出力（スナップショットシートをクリアして再出力）
7. ログ
8. 環境復元

## ■6 エラー処理

- 各エントリーポイント（Public Sub）は `On Error GoTo ErrHandler` を実装し、
  実行時エラーは操作ログへ「エラー有無=エラー」として記録した上で
  `Pr_環境復元` を必ず経由してから終了する。
- イベント入力の行単位の業務エラー（必須項目未入力、イベント種別不正、
  会員存在チェック不正など）は実行時エラーではなく明示的な検証ロジックで
  判定し、該当行の「処理状態」を「エラー」、「エラー内容」に理由を記録した上で
  後続行の処理を継続する。
- 拠出設定の終了処理は、対象の「有効」レコードが存在しない場合は何もしない
  ことで、再実行時の二重処理・二重終了を防止する。

## ■7 非機能要件

- **再実行可能性**: イベント入力は「処理済」行をスキップ、拠出設定は
  「有効」レコードの有無で終了処理をガード、月次実績はUpsertとすることで、
  途中で処理が中断しても何度でも安全に再実行できる。
- **保守性**: 列番号のハードコーディングを一切行わず、全シートアクセスは
  `Fn_ヘッダー列マップ取得` で得た列名ベースの `Dictionary` 経由で行う。
- **可読性**: 全プロシージャは前提・入力・出力・例外・拡張余地をコメントで明示し、
  1プロシージャ1責務を徹底する。
- **監査性**: イベント履歴・拠出設定履歴・操作ログはすべて追記専用とし、
  物理削除を行わない。
- **既知の制約**: スナップショット出力は会員マスタ（現在状態のみ保持）を
  参照するため、過去時点での氏名・所属会社の変更を厳密には遡及できない。
  過去の正確な所属を復元する必要がある場合は、イベント履歴からの状態再構築を
  拡張実装として別途検討する。

## ■8 テストケース

| No | 観点 | 手順 | 期待結果 |
|---|---|---|---|
| T1 | 入会 | 未登録MemberNoで入会イベントを入力し反映実行 | 会員マスタに新規行、拠出設定に有効レコード、イベント履歴に1件追加、処理状態=処理済 |
| T2 | 退会 | 在籍会員に退会イベントを入力し反映実行 | 会員状態=退会済、退会日設定、拠出設定が終了に変更 |
| T3 | 休会 | 在籍会員に休会イベントを入力し反映実行 | 会員状態=休会中、拠出設定が終了に変更 |
| T4 | 復帰 | 休会中会員に復帰イベントを入力し反映実行 | 会員状態=在籍、拠出設定に新規有効レコード(休会前口数を引継ぎ) |
| T5 | 口数変更 | 在籍会員に口数変更イベントを入力し反映実行 | 現在口数が更新、旧拠出設定終了・新拠出設定追加 |
| T6 | 入力エラー | 必須項目未入力の行を入力し反映実行 | 処理状態=エラー、エラー内容に理由が記録され後続行は処理継続 |
| T7 | 再実行 | T1〜T5実行後、同じシート状態で再度反映実行 | 処理済行はスキップされ、二重登録・二重履歴が発生しない |
| T8 | 月次実績 | 拠出設定と株価マスタを用意し月次実績更新実行 | 対象年月×MemberNo×会社コードの実績が算出され、再実行しても行数が変わらない |
| T9 | 単価未登録 | 株価マスタに単価がない会社コードで月次実績更新実行 | 当該会員はエラー件数に計上され処理が継続する |
| T10 | スナップショット | 在籍・退会済・休会中が混在する状態でスナップショット出力実行 | 基準日時点で在籍(休会中を含む)する会員のみが出力される |
| T11 | ログ | いずれかの処理を実行 | 操作ログに実行日時・処理名・件数・エラー有無・備考が1行追加される |
